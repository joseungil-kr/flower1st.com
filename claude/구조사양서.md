# 화환 사이트 구조 사양 (REV 1)

> 상위 8개 사이트 직접 해부에서 도출한 설계 규격.
> 프로젝트가 바뀌어도 이 문서는 그대로 적용된다. 변경 시 REV를 올린다.
>
> 표본 — binsoflower · citiflower · kinghaim · 정품화환.biz ·
> hallflower · allfuneralhall · myflora · baroflowers (2026-09-02 관측)

---

## § 1. 사이트 구조

되돌리기 어려운 순서로 배치. **1.1~1.4는 나중에 고치면 301이 필요하다.**

| 조항 | 규격 | 근거 |
|---|---|---|
| **1.1** | **호스트는 하나.** www 또는 non-www 중 하나로 301 통일. canonical·og:url·sitemap·robots·내부링크가 전부 같은 호스트 | baroflowers가 두 호스트 모두 200. IndexNow는 host 불일치 시 422 |
| **1.2** | **URL은 루트 직하 평면.** 시설명 + 핵심 키워드. 카테고리 접두어 없음. 계층은 브레드크럼과 내부링크로 표현 | 상위 6곳이 동일 방식 |
| **1.3** | **구분자는 붙여쓰기. 하이픈 금지**<br>`/밀양시민장례식장화환/` ○ &nbsp; `/밀양시민-장례식장/` ✕ | 공백(%20)은 상위 3곳이 사용. 하이픈 사용처 0곳 |
| **1.4** | **시설 1곳 = 페이지 1장.** 키워드 변형으로 URL을 늘리지 않는다. 화환·근조화환·장례식화환·부고화환은 한 문서의 title·본문·FAQ로 커버 | citiflower 시설당 20개 URL, kinghaim 폴더 4벌 복제 — 둘 다 중복 부채 |
| **1.5** | **4계층 사일로** — 홈 → 시도 → 시군구 → 시설. 허브도 각각 검색어를 노린다 | binsoflower 구조, 클릭 깊이 3 |
| **1.6** | **고아 페이지 0.** 브레드크럼(상향) + 형제 12개(횡) + 허브 전체 목록(하향) | funeralonw·allfuneralhall은 링크 없이 수동 투입에만 의존 — 취약 |
| **1.7** | **canonical은 자기 참조. 예외 없음** | citiflower·hallflower는 binjohwa를, allfuneralhall은 **GoDaddy 매물**인 funeralflower.com을 가리킴 |
| **1.8** | **사이트맵에 실제 페이지 전부.** robots.txt에 선언. 위장 사이트맵 금지 | allfuneralhall sitemap은 about·faq 등 15개뿐, funeralonw는 홈 1개 |
| **1.9** | **버티컬은 도메인 또는 최상위 폴더로 분리.** 장례·개업(전통시장)·결혼(예식장)을 섞지 않는다 | myflora가 `/funeral/`·`/wedding/` 분리 운영 |
| **1.10** | **정적 생성 + CDN. 외부 스크립트 0** | binsoflower 요청 8건(Astro+Cloudflare), citiflower 시설 페이지 요청 1건 |

## § 2. 시설 페이지 구조

**블록의 순서가 규격이다.** 01~04가 검색결과 노출 구간, 05 이하가 체류·전환 구간.

```
01  브레드크럼                          사일로 상향 연결
02  H1 — 시설명 + 핵심 키워드            완전일치. title보다 짧게
03  첫 문단 — 시설명·주소·시작가          스니펫이 잡히는 구간
04  1차 CTA — 전화 / 온라인              스크롤 없이 보이는 위치
05  시설 정보 블록                       이 페이지만의 데이터 ← 경계선
      주소·전화·빈소·안치·주차·부대시설·지도
06  상품 가격표 6~8종                    가격을 페이지 안에 노출
07  주문 절차 4단계
08  리본 문구 — 종교별
09  FAQ 4~6                            질문 문장에 시설명 포함
10  형제 링크 12 + 상위 허브 링크          고아 방지·사일로 순환
11  2차 CTA
```

> **05번 블록이 이 사양의 경계선이다.** 이 블록이 비면 나머지를 아무리 채워도
> 시설명만 치환된 껍데기이고, 그 순간 프로그래매틱 SEO가 아니라 도어웨이가 된다.

### 2.1 메타 공식

```
title        {시설명} {핵심어} 주문 · {보조어} 배송 | {브랜드}
             예) 밀양시민장례식장 화환 주문 · 근조화환 배송 | 브랜드

H1           {시설명} {핵심어}
             예) 밀양시민장례식장 화환

description  {시설명} 빈소로 {보조어}를 배송합니다. {시작가}부터.
             {마감시간}. {주소}. {시군구} 장례식장 화환 주문.

canonical    자기 자신 (percent-encoding 그대로)
og:          title / description / image 1200×630 / url / locale=ko_KR
JSON-LD      선택 — 상위 8곳 중 사용처 0. 승부처 아님
```

### 2.2 분량과 무게

| 항목 | 규격 | 관측된 경쟁 수준 |
|---|---|---|
| 본문 분량 | 1,500~2,300단어 | baroflowers 2,300 / binsoflower 1,200 / hallflower 1,200 / kinghaim 450 |
| 페이지 용량 | 10KB 이하 | citiflower 요청 1건 · binsoflower 8건 |
| 외부 스크립트 | 0 | 상위권 전부 0~1 |
| 형제 링크 | 12개 내외 | citiflower 30 / binsoflower 5 |
| 가격 노출 | 필수 | 8곳 전부 페이지 안에 노출 |

상한 2,300은 그 이상이 나쁘다는 뜻이 아니라 **현재 이 시장의 최고 수준**이다.
1,500단어를 못 채우면 페이지를 늘리기 전에 **시설 데이터를 먼저 보강**한다.

### 2.3 이미지 자산 — 빌드 전에 준비할 것

같은 이미지(상품 사진·대표 이미지)가 수백~수천 페이지에 반복 노출되는 구조이므로, 다음 사이트를 만들 때도
**빌드 전에** 아래를 준비해 둔다. 준비 없이 시작하면 페이지 전부가 텍스트만 남는다.

| 항목 | 규격 | 이유 |
|---|---|---|
| 상품/대표 이미지 | 사전 준비 필수 | facility_page 05번 블록 다음으로 검색결과 이미지 노출(썸네일 카드)에 영향 |
| 파일 크기 | 표시 용도에 맞게 리사이즈(예: 상품 썸네일 500px) + JPEG quality 75~80 압축 | 원본 그대로 쓰면 페이지당 수백KB, 대량 페이지에서 누적 |
| 배치 방식 | **외부 공유 파일**로 두고 여러 페이지에서 재사용 (`/assets/...`) | 브라우저 캐싱 — 방문자가 첫 페이지에서만 받고 나머지는 재다운로드 0 |
| base64 인라인 | **금지** (같은 이미지가 여러 페이지에 반복되는 경우) | 페이지마다 중복 전송됨 — 캐싱 이점이 없어져 전체 전송량이 외부파일 방식보다 수십~수백 배 커짐. 진짜 그 페이지 전용의 아주 작은 아이콘 1회성 용도가 아니면 쓰지 않는다 |
| 이미지 슬라이스 | 금지 | 여러 장을 이어붙여 하나처럼 보이게 하는 방식은 검색결과 썸네일에서 조각만 잘려 노출됨 |
| 텍스트 박힌 이미지 | 대표이미지(og:image) 용도는 무방, **본문 콘텐츠 대체 금지** | 이미지 속 텍스트는 스크린리더·크롤러가 실제 텍스트만큼 신뢰하지 않음. 가격·상품명 등 핵심 정보는 반드시 실제 HTML 텍스트로도 존재해야 함 |
| favicon / og:image | 빌드 전에 파일 확보, shell()에 태그 기본 포함 | 없으면 소셜 공유·브라우저 탭에서 브랜드 인식 저하 |

## § 3. 허브 페이지 구조

시군구 허브는 그 자체가 "밀양시 장례식장 화환" 검색어를 노리는 페이지다. 목록만 있는 페이지로 만들지 않는다.

```
브레드크럼
H1        {시군구} 장례식장 화환
첫 문단     {시군구} 장례식장 {N}곳에 배송합니다 · 시작가
CTA
시설 목록    그 시군구의 전 시설
상품 가격표   시설 페이지와 동일
인접 지역    같은 시도의 다른 시군구 12개
상위 허브    {시도} 전체 보기
```

**숫자를 문장에 넣는 것**이 목록형 페이지와 갈리는 지점이다.

## § 5. 적용 우선순위

효과 ÷ 비용 순.

1. **호스트 통일(1.1)** — Cloudflare 규칙 1개. 안 하면 이후 색인 작업이 절반으로 샌다
2. **커버리지 채우기** — 없는 페이지는 순위가 없다. 전국 1,098곳 기준
3. **사이트맵 정합성(1.8)·lastmod 정리** — IndexNow 전체 전송은 여기까지 끝난 뒤
4. **슬러그 교정(1.3)** — 301 필요. 한 지역 30개로 검증 후 전체 적용
5. **페이지 블록 순서 정비(§2)**
6. **버티컬 확장(1.9)** — 장례로 검증된 뒤 전통시장·예식장
