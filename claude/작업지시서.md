# 작업지시서 — 전국 장례식장 화환 사이트 생성

> 대상 폴더: `C:\project\flower-sitegen\`
> 실행 환경: VS Code + Claude Code (Windows)
> 최종 산출물: `out\` 폴더 (Cloudflare Pages에 그대로 업로드 가능한 정적 사이트)

---

## 0. 이 작업의 목적

네이버 "장례식장명 + 화환" 키워드군에서 상위 경쟁사(binsoflower, citiflower, kinghaim, 정품화환.biz)를
구조적으로 앞서는 정적 사이트를 **1차로 장례식장 전체(약 1,100곳)** 규모로 생성한다.

**성공 기준**
- 시설 1곳 = 페이지 1장, 고아 페이지 0개
- 전 페이지가 sitemap.xml에 포함되고 robots.txt에서 선언됨
- 페이지당 10KB 이하, 외부 요청 0건
- 빌드가 명령어 한 줄로 재현 가능 (데이터 수정 → 재빌드 → 재배포)

## 3. TASK 1 — 엑셀을 facilities.csv로 변환

**입력** `C:\project\flower-sitegen\자료\전국장사시설_정리.xlsx`

### 1-1. 먼저 구조를 파악하고 보고할 것

시트 목록, 각 시트의 헤더, 행 수, 시설 종류 구분 컬럼의 고유값을 출력한다.
**여기서 멈추고 컬럼 매핑을 사용자에게 확인받은 뒤 진행한다.** 추측해서 매핑하지 말 것.

### 1-2. 목표 스키마

```
sido,sigungu,name,address,phone,rooms,coffins,parking,extras,type,map
```

| 컬럼 | 내용 | 비고 |
|---|---|---|
| `sido` | 시·도 | "경상남도" 형태 정식명 |
| `sigungu` | 시·군·구 | 창원시처럼 구가 있으면 "창원시마산회원구" |
| `name` | 시설명 | URL과 제목에 그대로 쓰임 — **가장 중요** |
| `address` | 도로명 주소 | |
| `phone` | 시설 대표번호 | 주문번호 아님. 페이지에 그렇게 표기됨 |
| `rooms` | 빈소 수 | 숫자만 |
| `coffins` | 안치 가능 구수 | 숫자만 |
| `parking` | 주차 가능 대수 | 숫자만 |
| `extras` | 부대시설 | "주차장·접객실·유족대기실" 형태로 병합 |
| `type` | 운영 구분 | "사설(병원)", "공설" 등 |
| `map` | 지도 URL | 없으면 공란 |

**빈 값은 공란으로 둔다.** 생성기가 알아서 해당 줄을 렌더하지 않는다. 추정값을 채우지 말 것.

### 1-3. 필터

- 시설 종류가 **장례식장**인 행만 `facilities.csv`
- 화장시설·자연장지·봉안시설은 `facilities_기타.csv`로 분리 보관

### 1-4. 명칭 정규화 규칙

`name`이 곧 URL이자 검색어다. 아래 규칙을 순서대로 적용한다.

1. 앞뒤 공백 제거, 연속 공백 1개로 축소
2. **중간 공백은 제거하지 않는다.** "연세대학교 강남장례식장"처럼 실제 검색되는 형태는 유지
3. 괄호 안 부가설명이 주소·운영주체인 경우 제거 (예: `밀양시민장례식장(세종요양병원)` → `밀양시민장례식장`).
   단 괄호가 지점을 구분하는 경우는 유지 (예: `인천청기와장례식장(송림점)`)
4. `㈜`, `(주)` 등 법인 표기는 원본 유지
5. 명칭 끝에 "장례식장"이 없는 행은 목록으로 뽑아 보고 — 임의로 붙이지 말 것

### 1-5. 중복 처리

정규화 후 `name`이 겹치는 행이 있으면 URL이 충돌한다.

- 완전 동일 시설(중복 등록)이면 하나만 남기고 제거
- 서로 다른 지역의 동명 시설이면 `시군구 + 명칭`으로 변경 (예: `김해한솔장례식장`)
- 판단이 애매하면 목록으로 뽑아 사용자에게 확인

### 1-6. 검증 리포트 작성

`변환리포트.md`에 아래를 기록한다.

- 총 행 수, 시도별 시설 수
- **아래 기준선과 대조** (경쟁사 binsoflower가 공개한 커버리지, 전국 1,098곳)

```
경기 185 / 전남 130 / 경남 121 / 경북 121 / 충남 76 / 전북 74
서울 61 / 대구 56 / 부산 55 / 강원 53 / 충북 52 / 인천 35
광주 26 / 대전 19 / 울산 17 / 제주 11 / 세종 6
```

- 각 컬럼의 결측률 (address, phone, rooms, parking이 핵심)
- 중복 처리 내역
- 명칭이 이상한 행 목록

**시도별 숫자가 기준선보다 20% 이상 적으면 원본 데이터에 누락이 있다는 뜻이니 보고할 것.**

## 4. TASK 2 — build.py 수정 (URL 정책 변경)

현재 `build.py`는 시설 페이지 URL을 `/{시설명}/`으로 만든다.
이를 **`/{시설명}{화환}/`**으로 바꾼다. 아래 4곳을 모두 고쳐야 한다.

### 2-1. `facility_page()` — canonical과 반환 슬러그

```python
# 변경 전
canon = f"https://{C['domain']}/{enc(name)}/"
...
return name, shell(title, desc, canon, body)

# 변경 후
slug = f"{name}{KW}"
canon = f"https://{C['domain']}/{enc(slug)}/"
...
return slug, shell(title, desc, canon, body)
```

### 2-2. `facility_page()` — 형제 링크

```python
# 변경 전
sib = "".join(f"<li><a href='/{enc(s)}/'>{esc(s)} {esc(KW)}</a></li>" for s in siblings)
# 변경 후
sib = "".join(f"<li><a href='/{enc(s+KW)}/'>{esc(s)} {esc(KW)}</a></li>" for s in siblings)
```

### 2-3. `sigungu_page()` — 시설 목록 링크

```python
# 변경 전
lst = "".join(f"<li><a href='/{enc(r['name'])}/'>{esc(r['name'])}</a></li>" for r in rows)
# 변경 후
lst = "".join(f"<li><a href='/{enc(r['name']+KW)}/'>{esc(r['name'])} {esc(KW)}</a></li>" for r in rows)
```

### 2-4. 허브 페이지 슬러그는 그대로 둔다

`/경상남도장례식장/`, `/밀양시장례식장/`은 지금 형태가 맞다. 건드리지 말 것.

### 2-5. 이중 CTA 적용

현재 `cta()`는 전화 링크 하나만 만든다. 쇼핑몰 버튼을 추가한다.

```python
def cta():
    tel = C['phone'].replace('-', '')
    shop = C.get('shop_url')
    b = f"<a class='cta' href='tel:{tel}'>전화 주문 {esc(C['phone'])}</a>"
    if shop:
        b += (f"<a class='cta' style='background:#fff;color:var(--a);"
              f"border:2px solid var(--a)' href='{esc(shop)}' rel='nofollow'>"
              f"온라인 주문하기</a>")
    return b
```

> 쇼핑몰 URL은 **`https://fwith.co.kr`** 로 고정한다. http로 쓰면 혼합 콘텐츠 경고가 난다.
> `rel="nofollow"`는 외부 도메인으로 링크 가치가 새는 것을 막기 위함이며 제거하지 말 것.

## 8. TASK 6 — 색인 투입 (이 단계를 빠뜨리면 앞의 전부가 무의미)

경쟁사 1위 사이트는 내부링크도 사이트맵도 없이 색인됐다. 이 단계가 그 이유다.
**손으로 하루 100개씩 누르지 않는다.** 네이버는 2023-07-26부터 IndexNow를 지원하므로
1,100개를 POST 한 번으로 통보할 수 있다.

### 6-1. IndexNow 키 발급 (최초 1회)

```powershell
python indexnow_push.py --make-key
```

- 32자 키와 `out\<키>.txt` 파일이 생성된다
- 이 키 파일이 **배포된 사이트 루트에서 열려야** 한다 → `https://도메인/<키>.txt`
- 키는 config에 적어 두고 계속 재사용한다. 매번 새로 만들지 말 것

### 6-2. 배포 후 키 확인

```powershell
python indexnow_push.py --check-key --domain 도메인 --key <키>
```

`[정상]`이 떠야 다음으로 간다. 여기서 실패하면 전송이 403으로 거절된다.

### 6-3. 일괄 전송

```powershell
# 먼저 무엇이 나갈지 확인
python indexnow_push.py --domain 도메인 --key <키> --sitemap out\sitemap.xml --dry-run

# 실제 전송 (1,100개면 요청 1회로 끝난다)
python indexnow_push.py --domain 도메인 --key <키> --sitemap out\sitemap.xml
```

- 전송 결과는 `indexnow_log.csv`에 남는다
- 이후 페이지를 추가하면 `--new-only`로 **안 보낸 것만** 전송된다
- 조심스럽게 가려면 `--limit 300`으로 나눠 보내도 된다
- 응답 코드: 200/202 정상, 403 키 실패, 422 host 불일치, 429 과다요청(자동 재시도)

> IndexNow는 **변경 통보**이지 색인 보장이 아니다. 빙·얀덱스에도 함께 전달된다.

### 6-4. 서치어드바이저는 병행한다 (대체가 아니라 보완)

1. 사이트 등록 → 소유확인 → **사이트맵 제출** (필수. IndexNow와 별개)
2. RSS 제출 (신규 페이지 발행 시 수집 유도)
3. **수동 수집요청은 상위 30~50개 핵심 페이지에만** 쓴다
   — 대형 병원 장례식장, 주요 도시 허브 페이지
4. 다음 검색등록, 구글 서치콘솔에도 사이트맵 제출

### 6-5. 하면 안 되는 자동화

서치어드바이저 로그인 세션을 Selenium·Playwright로 조작해 수집요청 버튼을 반복 클릭하는 방식은
**하지 않는다.** 네이버 이용약관 위반이고 사이트 계정 자체가 제재 대상이 된다.
IndexNow가 공식 경로로 열려 있는 이상 감수할 이유가 없다.

### 6-6. 기록

`색인투입기록.md`에 전송 일시, 건수, 응답 코드를 남긴다. 2~4주 뒤 순위 관측의 기준이 된다.

## 10. 사용자에게 확인받아야 하는 항목

작업 중 아래는 **추측하지 말고 반드시 질문할 것.**

1. **도메인** — canonical과 sitemap 전체에 박히므로 빌드 전에 확정 필요
2. **브랜드명** — title 끝에 붙는 이름
3. **엑셀 컬럼 매핑** — TASK 1-1 결과를 보고한 뒤 확인
